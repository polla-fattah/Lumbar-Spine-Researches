%
%  ---------------------------------------------------------------------------
%  WHY THIS FILE EXISTS
%
%  chapter2.tex and chapter3.tex are each complete standalone documents, with
%  their own \documentclass, preamble and \end{document}. That is deliberate and
%  worth keeping: a chapter can be compiled and sent to a supervisor on its own
%  in a couple of seconds without building the whole thesis.
%
%  The cost of standalone chapters is that cross-chapter references cannot
%  resolve. Chapter 3 refers to \ref{ch:litreview} five times; compiled alone
%  those emit "Chapter ??". Only a single document containing both chapters can
%  resolve them, and only such a build can confirm that the gap -> research
%  question -> contribution numbering holds end to end.
%
%  ---------------------------------------------------------------------------
%  HOW IT WORKS -- and why the chapter files were NOT modified
%
%  The docmute package makes \input ignore everything in the included file up to
%  \begin{document} and after \end{document}. The chapter preambles are
%  therefore skipped automatically at build time.
%
%  This means chapter2.tex and chapter3.tex are byte-for-byte unchanged and keep
%  compiling standalone exactly as before. There are no duplicated bodies to
%  keep in sync, which is the usual failure mode of the alternative approach
%  (splitting each chapter into a preamble file plus a body file).
%
%  The consequence is that every package a chapter needs must be declared HERE,
%  because the \usepackage lines in the chapters are ignored. The preamble below
%  is the union of both chapter preambles. If you add a package to a chapter,
%  add it here too or the thesis build will fail while the chapter still works.
% ===========================================================================

% and the methodology references filed as records 111-149.
\addbibresource{../lumbar_spine_mri_ai_literature_inventory.bib}

% The inventory .bib carries internal bookkeeping fields (provenance note, the
% per-paper summary, the local PDF path). These are working metadata, not
% bibliographic data, so they are suppressed from the printed reference list.
% Leaving the note field in also breaks compilation, since it contains raw
% underscores that LaTeX reads as math subscripts.
\AtEveryBibitem{%
  \clearfield{note}%
  \clearfield{comment}%
  \clearfield{annotation}%
  \clearfield{abstract}%
  \clearfield{file}%
}
